# Security Policy

## Supported versions

Security fixes are provided for the latest tagged release. Users should upgrade
before reporting an issue that may already be fixed on `main`.

## Reporting a vulnerability

Do not publish unpatched vulnerabilities, malicious assets, private scene data,
or identifying information in a public issue. Use GitHub's **Security → Report a
vulnerability** flow when it is available. If private reporting is unavailable,
open an issue that contains no sensitive details and asks the maintainer to
establish a private contact channel.

Include the affected version, platform, impact, minimal reproduction steps, and
whether the report may be acknowledged publicly. Expect an initial response
within seven days. This is a volunteer-maintained project, so remediation timing
depends on severity and reproducibility.
